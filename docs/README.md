# docs/ — 템플릿 문서

템플릿 저장소 자체의 검토 기록과 보관 기록을 관리한다.
생성 프로젝트가 받는 문서는 `skeleton/` 아래에 있으며(`README.md`·`AGENTS.md`·스킬, 프로젝트 문서용 `skeleton/docs/`), 이 폴더는 생성 시 복사되지 않는다.
구성은 FastAPI 형제 템플릿의 `docs/` 와 같게 둔다.

## 폴더 구조

```text
docs/
├── README.md        # 목차와 작성 규칙 (이 파일)
├── reviews/         # 검토 기록 — YYYY-MM-DD-<영문-주제>.md (첫 기록을 남길 때 만든다)
└── archive/         # 보관 기록 — changelog/CHANGELOG-YYYY.md (CHANGELOG 가 200줄을 넘을 때 만든다)
```

구성도(`architecture/`)는 아직 없다. 재개발이 끝나면 형제 템플릿처럼 스캐폴드 흐름·런타임 구성도를 추가한다.

## 검토 기록 (`reviews/`)

버전 상향·도구 도입·라이브러리 유지처럼 판단 근거를 남겨야 하는 검토를 일자별로 기록한다. 변경 요약은 루트 [`CHANGELOG.md`](../CHANGELOG.md) 에 있다.

| 일자 | 문서 | 결정 | 반영 커밋 |
|---|---|---|---|
| 2026-11-23 | [jQuery 4.1.0 도입](reviews/2026-11-23-jquery-adoption.md) | 유지 — jQuery 등 DOM 유틸리티 미도입, 바닐라 JS 사용 | 이 기록과 같은 커밋 |
| 2026-11-23 | [공지 본문 위지웍 편집기](reviews/2026-11-23-wysiwyg-editor.md) | 보류 — 형제 자체 편집기의 바닐라 JS 이식을 권장안으로 정함 | 없음 |

## 작성 규칙

- 파일명은 `reviews/YYYY-MM-DD-<영문-주제>.md` 다. 같은 주제는 형제 템플릿과 같은 이름을 쓴다(`dependency-upgrade` 등).
- 문서 머리에 **일자**·**결정**(적용·보류·유지·폐기)·**대상**·**반영 커밋**(없으면 「없음」)을 목록으로 둔다. 필요하면 고정 조건·관련 기준·재검토 조건을 부기한다.
- 본문에는 배경, 실측 결과, 영향 판정, 미확인 항목, 재검토 조건을 포함한다. 수치에는 `실측`·`미측정` 상태를 부기하고, 릴리스 노트에서 인용한 내용은 출처를 명시한다.
- 검토 기록은 시점 기록이다. 버전 값을 사후 갱신하지 않고, 후속 처리는 처리 커밋과 함께 부기한다.
- 결정이 바뀌면 기존 문서를 삭제하지 않는다. 새 문서를 추가하고 기존 문서 머리에 `대체됨: <새 문서 링크>` 를 부기한다.
- 기준(규칙)이 바뀌는 결정은 `skeleton/ARCHITECTURE.md`·`stack-versions` 스킬에 반영하고, 이 폴더에는 판단 근거만 둔다.
- 문서를 추가하면 위 표에 한 줄을 추가하고, `CHANGELOG.md` 의 해당 일자 항목에서 링크한다.
- 보관 기록(`archive/`)은 현재 기준이 아닌 기록이다. 고치지 않는다. 보관 규칙은 루트 `AGENTS.md` 「문서 갱신」을 따른다.
